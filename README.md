# wace-survey — 오르카아이티 AI 도입의향 고객설문

ERP 고객사를 대상으로 AI 도입 의향·투자 의향·정부 지원사업 참여 가능성을 조사하는 설문.
공개 HTML 설문 페이지가 응답을 Apps Script 웹앱으로 POST하고, 응답은 **설문 기획자 소유의
구글 시트 한 곳**에만 적재된다. 서버 없음 · API 키 없음.

```
[응답자 브라우저]  →  POST  →  [Apps Script 웹앱]  →  [기획자 소유 구글 시트]
   설문 HTML                     실행: 소유자 권한         관리자 조회 화면
                                 (append-only)
```

## 배포 (Vercel)

`web/` 안의 설문 페이지 한 장만 공개되고, 나머지 내부 문서(설계안 PDF·DOCX 빌더·각종 가이드)는
배포 대상이 아니다. **저장소가 Private이어도 배포된 파일은 공개 URL로 열리므로** 이 경계가 중요하다.

| 설정 | 값 |
|---|---|
| Framework Preset | Other |
| **Root Directory** | **`web`** ← 반드시 지정. 비워두면 저장소 전체가 공개된다 |
| Build Command | (비움) |
| Output Directory | (비움) |

`.vercelignore`는 Root Directory 지정을 빠뜨렸을 때를 대비한 이중 방어다.
`web/robots.txt` + 페이지의 `noindex` 메타로 검색엔진 색인도 차단한다.

## 화면 구성

13개 화면을 순차 진행한다. **설문상 문항은 9개**다.

```
intro → basic1 → basic2 → q1 q2 q3 q4 q5 q6 q6_1 q7 [q7_1] → final
        회사·담당자  규모·ERP                                    연락처+동의
```

| 구간 | 내용 | 필수 |
|---|---|---|
| `basic1` | 회사명·담당자 성명·직책 | 회사명, 성명 |
| `basic2` | 업종·종업원 수·연매출·사용 ERP (칩 그리드) | 연매출 제외 |
| `q4` | 19개 AI 활용 분야를 업무 영역 3개의 접이식 목록으로 묶고, 그 아래에 기타·해당 없음 | 합계 1개 이상 |
| `final` | 전화·이메일·개인정보 동의 | 전부 |

**연락처(전화·이메일)는 마지막 화면에서 받는다.** 설문 시작 직후 연락처를 요구하면 이탈이 커서,
의향 문항을 먼저 받고 "연락 받으실 곳"이라는 맥락이 생긴 뒤에 묻는다. 회사명·성명만 앞에 두어
응답을 식별한다.

Q4는 `생산 현장에서` / `설계 · 개발 업무에서` / `경영 · 사무 업무에서` 세 영역을 접이식(`.acc`)으로
두고, 기본으로 첫 영역만 펼쳐 둔다. **시스템 약어(MES·PLM·ERP)는 제목이 아니라 보조 라벨이다** —
응답자는 시스템 이름보다 자기 업무를 먼저 인식한다. 접힌 영역도 머리말에 선택 개수(`2 / 6`)를
계속 보여주고, 아무것도 고르지 않은 채 넘어가려 하면 세 영역을 모두 펼친 뒤 오류를 띄운다.

아무 분야도 고를 것이 없는 응답자를 위해 `아직 정하지 못했다`(`data-exclusive`)를 두었다 —
다른 항목이 하나라도 선택돼 있으면 이 보기는 숨겨진다(접힌 영역의 선택이 조용히 지워지는 것을 막는다).

## 디자인 토큰

색·크기·간격은 `:root`의 CSS 변수로만 정의한다. 개별 규칙에 임의 값을 적지 않는다.

| 묶음 | 변수 |
|---|---|
| 표면 | `--bg` `--surface` `--surface-2` `--surface-3` |
| 테두리 | `--edge`(장식) `--edge-i` `--edge-i-hover`(상호작용) |
| 글자 | `--text` `--text-2` `--muted` |
| 강조 | `--gold` `--gold-hi` `--on-gold` `--sel-bg` `--req` `--ok` |
| 크기 | `--fs-*` (h1·qtitle·opt·meta·input·btn·rail) |
| 여백·치수 | `--s1`~`--s5`, `--r-*`, `--h-btn` `--h-opt` `--h-input`, `--maxw` |

톤은 **인쇄 문서**를 기준으로 잡았다 — 중성·웜 그레이 표면, 모서리 반경 3px, 카드 상단의 골드
괘선(레터헤드), 제목 아래 구분선, 문항 앞의 조항식 번호(`Q4.`). 강조색은 CTA·진행률·선택 표시에만 쓴다.

한글 세리프(AppleMyungjo·바탕)는 쓰지 않는다. OS마다 글꼴이 갈리는 데다 굵기가 하나뿐이라
굵은 제목이 합성되어 지저분해진다. 문서 인상은 글꼴이 아니라 괘선·번호·여백으로 만든다.

지켜야 하는 두 가지.

- **선택지·입력칸의 테두리(`--edge-i`)는 맞닿은 표면 대비 3:1 이상**을 유지한다(WCAG 1.4.11).
  이전 버전은 1.2:1이라 "어디가 누를 수 있는 칸인지" 보이지 않았다.
- **입력칸 글자는 16px 미만으로 내리지 않는다.** 그 아래면 iOS Safari가 입력 시 화면을 확대한다.

라디오·체크박스는 네이티브 컨트롤을 숨기고 22px 표식을 직접 그린다(원형=단일, 사각=복수).
`.opt > input` 을 타입 없이 선택하면 같은 카드 안의 "기타" 자유입력칸까지 숨겨지므로
반드시 `input[type="radio"], input[type="checkbox"]` 로 한정한다.

## 설정

설문 페이지 `<script>` 상단 두 상수만 채우면 동작한다.

```js
const ENDPOINT = "";            // Apps Script 웹앱 /exec URL. 비우면 수동 접수 화면으로 폴백
const TURNSTILE_SITE_KEY = "";  // 선택. 비우면 허니팟만으로 동작
```

Turnstile **시크릿 키는 이 저장소에 두지 않는다.** Apps Script의 스크립트 속성
(`TURNSTILE_SECRET`)에만 저장한다.

## 배포 시 주의

- 웹앱은 반드시 **실행: 나(소유자)** + **액세스: 모든 사용자** 로 배포할 것.
  전자를 틀리면 응답자에게 구글 로그인을 요구하게 되고, 후자를 틀리면 외부 제출이 막힌다.
- 코드 수정 후에는 저장만으로 반영되지 않는다. **배포 관리 → 새 버전 → 배포** 를 거쳐야 한다.
- 문항을 바꿀 때는 HTML의 `collectAnswers()` 반환 키와 `.gs`의 `COLUMNS` 배열을 함께 고친다
  (현재 20개 항목, 순서 일치). Q4는 영역이 셋이어도 `name="q4"` 하나로 모아 한 열에 저장한다.

## 제출 신뢰성 (중복 차단 + 재시도)

Apps Script는 POST 응답을 `script.googleusercontent.com`의 일회용 URL로 리다이렉트해 돌려준다.
**이 응답 회수 단계가 구글 쪽 사정으로 간헐적으로 실패한다** — 2026-08-06 실측 기준 6회 중 3회가
9~25초를 끌다 404로 끝났다. 이때 `doPost`는 이미 끝나 시트 저장까지 마친 상태라, 페이지에는
"접수 실패"가 뜨는데 시트에는 행이 남는다. 그대로 재시도하면 같은 응답이 두 줄 쌓인다.

그래서 이렇게 처리한다.

| 위치 | 처리 |
|---|---|
| HTML | 제출 1건당 `submissionId`를 한 번 발급. 회당 8초 상한으로 끊고 최대 4회 재시도(간격 0.8·2·3.5초) |
| `.gs` | 같은 `submissionId`를 `DEDUPE_TTL_SEC`(10분) 안에 다시 받으면 저장을 건너뛰고 `{ok:true, duplicate:true}` 반환 |

중복 판정과 저장은 같은 `LockService` 락 안에서 일어나므로 재시도 두 건이 동시에 도착해도 한 번만 저장된다.
`submissionId`는 시트 열로 저장하지 않는다(캐시에만 둔다) — 열을 늘리면 기존 시트의 헤더와 어긋난다.

유량제한(`rate`)·캡차(`captcha`) 거부는 재시도해도 결과가 같으므로 즉시 수동 접수 화면으로 넘긴다.

## 스팸 방어

허니팟 → 전역 유량제한(분당 30건) → Turnstile 서버측 검증(선택) → 필드 화이트리스트·길이 제한
→ 시트 수식 인젝션 차단.

웹앱 URL은 자격증명이 아니며 append-only라 기존 응답의 조회·수정·삭제가 불가능하다.
최악의 경우는 스팸 행 유입이고, 대응은 시트에서 해당 행을 삭제하는 것이다.
